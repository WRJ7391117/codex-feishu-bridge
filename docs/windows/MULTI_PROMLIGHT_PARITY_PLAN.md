# Windows 多灯对齐 Mac：方案与验收门

状态：多用户、多灯代码已进入本机候选验证；尚未完成双灯双用户真机、签名安装和最终独立审计。禁止据此宣称正式发布或完整验收通过。

## 当前候选实现

- `PromLightRegistry`：逐设备/owner/世代配置、每人默认灯、revision、原子落盘与等待解绑。
- `PromLightFleetService`：独立灯工作器、逐灯写入、旧单灯保守迁移及人工导入，不控制其他灯。
- `PromLightTurnOrigins`：记录确切 Task/turn 来源；同 Task 多用户场景只向需要处理者显示 HumanGate。无法确定多用户来源时保持 Running，不猜测处理者，用户需在 Codex 查看确认事项。
- `PromLightRetryPolicy`：逐灯带抖动指数退避，上限 60 秒；目标变化及确认成功重置。
- App：使用者/设备/灯选择、命名、默认、解绑确认、旧关联导入。飞书：逐灯设置和 Task 管理、分页、一次性目标固定卡片。
- 历史 v1 配置保留。注册表损坏或未知版本均拒绝控制，不恢复为“第一盏灯”。

发布验收仍以 [RELEASE_GATES.md](RELEASE_GATES.md) 为准。

## 现状与第一道保护

Mac 基线为 Resources/bridge/feishu_codex_bridge.py 的 bind_promlight、owned_promlight_lamp、set_default_promlight、unbind_promlight、set_promlight_task_subscription、refresh_promlight_lamp，及 tests/test_promlight.py。

Mac 按 lamp_id 保存 owner、relay_ref、名称、独立 Task 列表、默认标记、状态、revision 和解绑收尾。Windows 原先只有一份全局绑定，按枚举顺序选择首个设备。先增加精确设备锁定及持久化：多设备且无目标时拒绝写入，原灯离线不转移到另一盏灯。这是防串灯保护，不是完整多灯支持。

## 模块与行为契约

| 模块 | 必须实现的行为 |
| --- | --- |
| 设备发现 | 列出全部兼容接口，以稳定设备身份区分，不能按名称、顺序或在线数量路由。离线已绑定灯继续显示。USB/BLE 两个接口只有经验证属于同一物理灯才合并；否则明确提示，不能猜测。 |
| 身份与授权 | 每盏物理灯只能绑定一个已授权使用者；同一使用者可有多灯。飞书只显示并操作自己的灯。Bot 身份或使用者授权失效后立即停止该范围提醒，旧卡片不能继续修改。 |
| 独立配置 | 每盏灯有显示名称、所属使用者、独立 Task 列表、在线状态、默认标记、最后投递结果。重命名只改显示名称，不修改蓝牙名称、系统配对或关联。 |
| 默认灯 | 每位使用者最多一盏默认灯。默认仅用于首次选择/无显式目标的交互，不广播、不迁移已有 Task，不覆盖卡片明确携带的目标。默认灯离线不能由其他灯接管。 |
| Task 关联 | 灯与 Task 是多对多：一盏灯可观察多 Task，一个 Task 可被同一用户的多灯观察。添加时重新校验实际 Task 可见性和项目权限；移除关联不影响其他灯。 |
| 状态计算 | 分灯汇总关联 Task：错误 > 等待人工 > 运行 > 空闲。同一 Task 的变化只扇出到实际关联灯，连接错误不得覆盖无关灯。归档/删除/撤权后重新计算。 |
| 投递与重连 | 每灯独立串行写入、状态 revision、ACK、超时和有界退避。一盏灯写入失败不阻塞其他灯。重连发送最新状态而非重放过期中间状态；ACK 不表述成肉眼灯效验证。 |
| 解除绑定 | 只清理目标灯 Task 关联，先转为空闲；离线时保留 pending-unbind，重连后收尾，避免旧黄色/红色残留。过程中不得重新分配给其他用户。蓝牙配对不删除。 |
| App | 原生设备列表和明确选择器；绑定已授权使用者；重命名、默认、关联管理、只对选中灯测试。关键操作显示灯名和短身份提示。窄窗口、键盘、深浅色均可用。 |
| 飞书 | 控制中心逐灯展示，设置与关联卡片始终标明目标。每个一次性 capability 在服务端绑定 sender、Bot 世代、lamp_id、revision 与项目范围，不能用客户端任意 device ID 路由。切换另一张卡片不改变旧卡目标。 |
| 存储与迁移 | 新版配置按设备保存并原子写入。旧单灯数据保留备份；目标唯一且有可靠证据时迁移，否则要求在 App 明确选择旧关联应归属哪盏灯。损坏、未知版本不默默恢复为另一盏灯。 |

## 示例

- 桌面灯关联开发 Task A、B；门口灯关联发布 Task C。A 运行、C 等待确认时，桌面灯黄常亮，门口灯黄闪。
- 桌面灯、门口灯同时关联 A：A 完成后两盏灯分别更新，任意一盏离线不妨碍另一盏。
- 使用者甲拥有灯 A，乙拥有灯 B：乙转发或重放 A 的卡片必须被拒绝，不能查询甲的 Task。

5. 模拟多设备回归，再做至少两盏真灯的 USB/BLE 实测，独立审计通过后才能纳入 Windows release。

## 必须通过的验收

- 0、1、2、3 设备；枚举乱序；同名灯；目标离线且另一盏在线；App 重启。
- 一灯多 Task、一 Task 多灯、两用户各自多灯；默认切换不改变已有绑定。
- A 写入超时、B 正常；旧 revision 不覆盖新状态；断线期间任务完成后重连显示空闲。
- 离线解绑/重连收尾；解绑途中重新绑定被拒绝；取消单条关联不清空其他灯。
- 错误 owner、过期/复用 capability、身份世代变化、项目撤权、Task 归档。
- 旧配置可迁移/有歧义/损坏/未知版本；无硬件时不能声称灯效验证通过。

真机证据必须分别记录灯、Task 场景、程序 ACK 与用户实际观察；模拟测试不能替代双灯验收。
